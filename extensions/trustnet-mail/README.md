# TrustNet Mail 1.1

Chrome/Edge Manifest V3 implementation for Gmail opened messages. Outlook Web is unsupported: paste the selected email in the website's Email mode. Chrome and Edge APIs and DOM/navigation fixtures have been tested; actual installation and live Gmail extraction have not yet been verified. Gmail DOM changes can break extraction.

1. Start the full stack with `start-dev.bat`, including the phishing runtime used for embedded links.
2. Open `chrome://extensions` (Chrome) or `edge://extensions` (Edge), enable Developer mode, choose **Load unpacked**, and select this folder.
3. Open the extension's Options. Select the fixed localhost gateway and sign in with your existing TrustNet account. Create an account on the website first if needed. Passwords are not saved. The access token remains in trusted extension session storage, never the email DOM; reconnect after expiry or browser restart.
4. Reload Gmail, open/expand a message, then click its **Scan message** control. Scanning happens only on click. Multiple expanded messages have separate controls. Quoted text inside the selected body is included. Hidden/collapsed content and attachments are excluded.
5. Wait for the panel. Cancellation/navigation invalidates stale results. Disconnected, unsupported or oversized content gives a manual-paste instruction rather than a safe verdict.

Only Gmail and the two fixed localhost gateway origins are permitted. No arbitrary fetch proxy, inbox API, Gmail password access, mail modification, tracking images loaded by TrustNet, or provider calls are used. A normal message scan does not open destinations. Optional Groq is always off in this extension. Local requests include visible body, subject, claimed sender and displayed-link text/href. Reply-to/header authentication is unavailable from this adapter.

After a saved message scan, **Check this website** explicitly requests a separate backend website inspection for that saved link. The note beside the button explains that the backend contacts the destination. The panel shows domain/IP/TLS/static-page observations, why each matters, separate model assessment, and checks that could not be completed. JavaScript is not run and forms are not submitted. The timestamped snapshot is saved in history without replacing the original quick warning. Completed snapshots are reused; unavailable checks remain retryable. If the service worker restarts, scan the message again before inspecting a link.

The selected predictor has limited English SMS/email training and collection-specific evaluation. Modern inbox reliability is not established; low scores do not verify sender identity. AI authorship is not assessed. Positive/negative highlights are partial changes in the complete deployed probability when spans are masked, not probability percentages for individual words. A long/slow request may have no model highlights because an additional masked inference would exceed the attribution budget; unavailable evidence is displayed honestly.

Run the repository worker contract tests with `node --test extensions/trustnet-mail/tests/worker.test.cjs` from the repository root. External development QA also covers DOM extraction, stale navigation and actual authenticated API/collector calls with fixture Chrome APIs. These are not live Gmail/browser installation tests. Live Gmail verification was skipped at the user's request. Chrome/Edge are the intended targets; Firefox, Safari and other browsers are not verified or promised.

Build and automated verification (Node 24): `npm ci --ignore-scripts`, `npm test`, then `npm run build` in this directory. The build validates JavaScript and permissions, rejects HTML interpolation in the content script, and copies only 14 runtime files to `dist/trustnet-mail`, with SHA-256 checksums. Load that generated folder, or this source folder. Development dependencies are not shipped.

English and Roman Hindi/Hinglish result summaries are available from the language selector. Technical records remain in English. The same result can change language without sending the email again. An unknown verdict or failed link check never becomes a low-warning result. Message scans do not contact links. The only clickable result link is **Open full report**, pointing to the local TrustNet website and requiring the owner to sign in. Extracted addresses remain inert text. DOM unit tests use fixtures with LinkeDOM; no real mailbox or browser installation is used. Live Gmail remains unverified by explicit user instruction.

The panel consumes the backend `presentation` contract. Missing/failed checks remain incomplete; positive evidence can still appear in reasons. Wording and design-token copies come from `shared/presentation` during `npm run build`. After pulling changes, build and reload the unpacked extension. No live Gmail/manual browser test was run for this submission.

Connection troubleshooting: after updating, reload TrustNet Mail once at chrome://extensions (or edge://extensions), then reopen Connect. The options page loads its translation catalog before rendering. Login waits at most 10 seconds for the API, and the Connect UI recovers within 15 seconds if its service worker does not answer. Wrong credentials, an offline gateway and a broken extension response do not leave the button permanently disabled. Passwords are cleared after every attempt. Automated options-page tests execute the actual HTML script order, including successful login, rejection and a hung worker; live Gmail remains unverified.
